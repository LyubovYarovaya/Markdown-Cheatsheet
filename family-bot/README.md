# 🏡 Family Hub — телеграм-бот и мини-приложение для семьи

Списки покупок по категориям, вишлисты (общий и личные), учёт трат — всё в одном
Telegram-боте с веб-приложением внутри. Ссылки на товары бот разбирает сам:
вытягивает название, цену и картинку и раскладывает по категориям.

## Что умеет

**🔗 Ссылки → товары.** Кидаешь боту ссылку — он читает страницу (Open Graph и
schema.org), достаёт название, цену, картинку и магазин, определяет категорию по
ключевым словам и кладёт в нужный список. Категорию можно поправить кнопкой под
сообщением.

**🔁 Дубли не плодятся.** Если такая ссылка уже сохранена, бот не заводит второй
товар, а показывает существующий: в каком списке лежит, кто и когда добавил.
Ссылки сравниваются по сути — `http`/`https`, `www`, хвостовой слэш и utm-метки
игнорируются. Нужна копия — кнопка «Всё равно добавить».

**🛍 Списки покупок.** Из коробки: Техника, Кухня, Квартира, Текстиль, Baby,
Разное. Свои категории добавляются в приложении. У каждой позиции — цена,
магазин, заметка, статус «куплено», кто добавил.

**🎁 Вишлисты.** Общий на двоих плюс личный у каждого участника. Создаются
автоматически.

**🔗 Публичные ссылки.** Любую категорию (например, Baby) или вишлист можно
открыть по ссылке. Гость заходит с телефона без Telegram, видит список и жмёт
«Забронировать» — остальные видят, что подарок уже занят. Свою бронь можно снять
с того же устройства. **Для личных вишлистов брони скрыты от владельца** —
сюрприз остаётся сюрпризом.

**💸 Траты.** Пишешь боту `450 бензин` или `1200 грн аптека ежемесячная` — он
определяет категорию (машина, здоровье, квартира, продукты, baby, подписки,
одежда, развлечения) и записывает. Траты бывают разовые, ежемесячные,
ежеквартальные и ежегодные. Регулярные платежи заводятся шаблоном и отмечаются
кнопкой «Оплатить». В приложении — сводка по месяцу: итог, разбивка по
категориям, план по регулярным платежам, поддержка нескольких валют.

**🔔 Напоминания о регулярных платежах.** У шаблона регулярной траты есть дата
следующего платежа. За пару дней до срока бот пишет обоим участникам семьи:
сумма, категория, когда платить — и две кнопки: «Оплатили» (записывает трату и
переносит срок на следующий период) и «Пропустить» (двигает срок без траты).
Просроченные платежи бот напоминает каждый день, пока их не закроешь.
Если ноутбук спал в назначенный час, напоминание придёт при первом же
просыпании, а не потеряется.

**👫 Общее пространство.** `/invite` даёт ссылку — по ней вторая половинка
попадает в ту же семью, и списки с тратами становятся общими.

## Быстрый старт: одна команда

```bash
git clone -b claude/telegram-shopping-expenses-bot-7rboan https://github.com/LyubovYarovaya/Markdown-Cheatsheet.git
cd Markdown-Cheatsheet/family-bot
./start.sh                 # Windows: powershell -ExecutionPolicy Bypass -File .\start.ps1
```

Скрипт сам создаст виртуальное окружение, поставит зависимости, спросит токен
бота, поднимет https-туннель через `cloudflared` и подставит его адрес в `.env`.
Дальше — `/start` в боте. Остановить — `Ctrl+C`.

Если `cloudflared` не установлен, скрипт всё равно запустит бота (ссылки на
товары и траты работают), но мини-приложение и публичные ссылки будут
недоступны — им нужен https-адрес.

Запустить без туннеля намеренно: `SKIP_TUNNEL=1 ./start.sh`.

### Если приложение не открывается

Две проверки, обе без гадания:

- **В боте** — команда `/diag`. Показывает текущий адрес и стучится по нему
  снаружи: жив ли туннель, отвечает ли приложение, открывается ли страница.
- **В терминале** — `python3 doctor.py` (Windows: `py doctor.py`). Проверяет
  `.env`, приложение на localhost, процесс туннеля, публичный адрес, токен
  и — отдельно — не ведёт ли кнопка меню в BotFather на устаревший адрес.
  В конце печатает нумерованный список, что делать.

Самая частая причина: кнопка нажата в старом сообщении, а в ней зашит адрес
прошлого запуска. Лечится командой `/start` — нижняя клавиатура обновится.

### Чтобы адрес не менялся

Бесплатный `cloudflared` выдаёт новый адрес при каждом запуске. Кнопка «Открыть
приложение» несёт в себе конкретный URL и остаётся в чате навсегда — поэтому
после перезапуска старые кнопки показывают «не удалось найти IP-адрес», а
ссылки на вишлисты, которые ты уже раздала, перестают открываться.

Бот замечает смену адреса сам: при старте он пишет всем участникам и обновляет
нижнюю клавиатуру. Но ссылки для гостей приходится раздавать заново.

Лечится постоянным доменом — у ngrok он бесплатный, один на аккаунт:

1. [dashboard.ngrok.com](https://dashboard.ngrok.com) → *Domains* → *Create Domain*
2. `ngrok config add-authtoken <токен из дашборда>`
3. в `.env`: `NGROK_DOMAIN=твой-домен.ngrok-free.app`

`start.sh` увидит домен и поднимет туннель через ngrok. Адрес больше не
меняется — ни кнопки, ни ссылки на вишлисты не протухают.

## Ручная установка

1. **Создай бота** у [@BotFather](https://t.me/BotFather) → `/newbot` → сохрани токен.

2. **Настрой окружение:**
   ```bash
   cd family-bot
   cp .env.example .env       # впиши BOT_TOKEN и PUBLIC_URL
   python -m venv .venv && .venv/bin/pip install -r requirements.txt
   ```

3. **Публичный HTTPS-адрес.** Telegram открывает мини-приложение только по https,
   и по этому же адресу работают ссылки для гостей. Для локального запуска:
   ```bash
   cloudflared tunnel --url http://localhost:8080   # или ngrok http 8080
   ```
   Полученный адрес впиши в `PUBLIC_URL`.

4. **Запусти:**
   ```bash
   .venv/bin/python -m app.main
   ```
   Или в докере: `docker compose up -d --build`.

5. В боте нажми `/start` → «🛍 Открыть приложение». Отправь `/invite` мужу.

Чтобы кнопка меню в Telegram тоже открывала приложение:
BotFather → `/mybots` → бот → *Bot Settings* → *Menu Button* → указать
`https://твой-адрес/app/`.

## Переменные окружения

| Переменная | Зачем |
|---|---|
| `BOT_TOKEN` | токен от @BotFather |
| `PUBLIC_URL` | публичный https-адрес приложения |
| `DATABASE_URL` | по умолчанию SQLite; для Postgres — `postgresql+asyncpg://…` |
| `DEFAULT_CURRENCY` | валюта по умолчанию, `UAH` |
| `BOT_MODE` | `polling` (по умолчанию), `webhook` или `off` |
| `WEBHOOK_SECRET` | секрет для режима webhook |
| `TIMEZONE` | часовой пояс для напоминаний, `Europe/Kyiv` |
| `REMINDER_HOUR` | во сколько по местному времени напоминать о платежах, `10` |
| `REMIND_DAYS_BEFORE` | за сколько дней предупреждать, `2` |
| `DEV_TG_ID` | **только для локальной отладки**: пускает в API без подписи Telegram |

## Как устроено

```
app/
  main.py            FastAPI + запуск бота (polling или webhook) в одном процессе
  models.py          БД: семьи, пользователи, списки, товары, категории трат, траты
  auth.py            проверка подписи initData из Telegram Mini App
  api/               REST: списки, товары, траты, сводка, публичные страницы
  bot/               хендлеры и клавиатуры aiogram
  services/
    link_parser.py   Open Graph + JSON-LD + микроразметка → название, цена, фото
    categorizer.py   выбор категории по ключевым словам и по пути в URL
    quick_expense.py разбор «450 бензин» → сумма, валюта, категория, периодичность
    recurring.py     сроки регулярных платежей: следующий, просрочка, оплата
    items.py         добавление товара и поиск дублей по ссылке
    defaults.py      стартовые категории и вишлисты для новой семьи
web/
  index.html app.js  мини-приложение (ванильный JS, тема Telegram)
  share.html share.js публичная страница списка с бронированием
```

Данные разделены по семьям: каждый запрос проверяет, что список или трата
принадлежат семье пользователя. Публичные страницы доступны только по случайному
токену и только пока шеринг включён — выключил, и старая ссылка отдаёт 404.

## Тесты

```bash
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest
```

Покрыты: подпись initData (валидная, подделанная, просроченная), автокатегории,
парсинг Open Graph и JSON-LD, сравнение ссылок и защита от дублей, разбор
быстрых трат, расчёт сроков регулярных платежей (включая 31 января → 28 февраля
и пропущенные периоды), рассылка напоминаний, сценарии API — создание семьи,
товары, траты и сводка, шеринг с бронированием и скрытие броней от владельца
вишлиста.

Схема базы догоняется автоматически: при обновлении кода новые колонки
доливаются в существующую базу, данные не теряются.
